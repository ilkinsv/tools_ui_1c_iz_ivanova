# Реализация Универсального Инструмента Управления Версиями 7.0.3

## Обзор реализации

Данный проект представляет собой полную реализацию системы управления версиями 7.0.3 
с поддержкой расширений, выполненную в двух вариантах:

1. **Реализация на языке 1С (BSL)** - `src/builder/Классы/СистемаВерсий7.0.3.os`
2. **Реализация на Python** - `src/builder/Классы/СистемаВерсий7.0.3.py`

Обе реализации полностью функциональны и предоставляют идентичный API.

## Архитектура системы

### Основные компоненты

#### 1. ИнформацияОВерсии (VersionInfo)
Класс для хранения и управления информацией о версии:
- Номер мажорный (major)
- Номер минорный (minor) - шаг изменения 99
- Номер патч (patch) - диапазон 0-999
- Дата релиза
- Описание и список изменений
- Методы сравнения версий

#### 2. Расширение (Extension)
Класс для создания и управления расширениями:
- Уникальный идентификатор
- Имя и описание
- Версия и автор
- Система зависимостей
- Точки расширения (hooks)

#### 3. РеестрРасширений (ExtensionsRegistry)
Централизованное управление расширениями:
- Регистрация расширений
- Поиск по идентификатору
- Управление точками расширения
- Проверка зависимостей

#### 4. МенеджерВерсий (VersionManager)
Основной управляющий компонент:
- Инициализация версий
- Обновление версий (патч, минор)
- Сохранение/загрузка конфигурации
- Проверка совместимости платформ

#### 5. Логгер (Logger)
Многоуровневая система логирования:
- 4 уровня логирования (Ошибка, Предупреждение, Инфо, Отладка)
- Запись в файл
- Буферизация сообщений
- Временные метки

## Особенности версии 7.0.3

### Уникальная система версионирования

Формат версии: `X.YYY.ZZZ`

- **Мажорная версия (X)** - крупные изменения, обратная совместимость может нарушаться
- **Минорная версия (YYY)** - шаг изменения 99 (0, 99, 198, 297...)
- **Патч версия (ZZZ)** - диапазон 0-999, инкремент на 1

Примеры корректных версий:
```
7.0.3     - Начальная версия
7.0.250   - Патч обновление
7.99.0    - Минорное обновление (+99 к минорной)
7.99.500  - Патч после минорного
7.198.0   - Следующее минорное
8.0.0     - Мажорное обновление
```

### Система расширений

#### Создание простого расширения

```python
# Python
расширение = СоздатьРасширение("my.plugin", "Мой плагин", "1.0.0")
расширение.автор = "Разработчик"
расширение.описание = "Описание функционала"

# Добавление точки расширения
расширение.добавить_точку_расширения(
    "ПриЗапуске",
    lambda p: print("Плагин запущен!")
)

# Регистрация
реестр.зарегистрировать_расширение(расширение)
```

```bsl
// 1С
Расширение = СоздатьРасширение("my.plugin", "Мой плагин", "1.0.0");
Расширение.Автор = "Разработчик";
Расширение.Описание = "Описание функционала";

// Добавление точки расширения
Расширение.ДобавитьТочкуРасширения("ПриЗапуске", 
    "Сообщить(""Плагин запущен!"");");

// Регистрация
РеестрРасширений.ЗарегистрироватьРасширение(Расширение);
```

#### Зависимости между расширениями

```python
расширение.добавить_зависимость(
    "required.plugin",
    "1.0.0",      # Минимальная версия
    "2.0.0"       # Максимальная версия (опционально)
)
```

### Точки расширения

Стандартные точки расширения:
- `ПриЗапуске` - вызывается при старте системы
- `ПередЗакрытием` - вызывается перед завершением
- `ПередСохранением` - перед сохранением данных
- `ПослеЗагрузки` - после загрузки конфигурации
- `ПриОбновленииВерсии` - при изменении версии

Пользовательские точки расширения поддерживаются.

## API Reference

### Глобальные функции

| Функция | Описание | Возвращает |
|---------|----------|------------|
| `СоздатьМенеджерВерсий()` | Создание менеджера версий | МенеджерВерсийКласс |
| `СоздатьРеестрРасширений()` | Создание реестра расширений | РеестрРасширенийКласс |
| `СоздатьЛоггер()` | Создание логгера | ЛоггерКласс |
| `СоздатьРасширение(Идент, Имя, Версия)` | Создание расширения | Расширение |
| `СоздатьВерсию(Маж, Мин, Патч, Опис)` | Создание версии | ИнформацияОВерсии |

### Методы МенеджерВерсий

| Метод | Параметры | Описание |
|-------|-----------|----------|
| `инициализировать_версию` | Мажорный, Минорный, Патч, Описание | Инициализация новой версии |
| `получить_текущую_версию` | - | Получение текущего объекта версии |
| `следующая_патч_версия` | - | Увеличение патч версии (+1) |
| `следующая_минорная_версия` | - | Увеличение минорной версии (+99) |
| `сохранить_конфигурацию` | Путь к файлу | Сохранение в JSON |
| `загрузить_конфигурацию` | Путь к файлу | Загрузка из JSON |
| `проверить_совместимость_платформы` | Строка версии | Проверка платформы 8.3.12+ |

### Методы РеестрРасширений

| Метод | Параметры | Описание |
|-------|-----------|----------|
| `зарегистрировать_расширение` | Расширение | Регистрация расширения |
| `расширение_существует` | Идентификатор | Проверка существования |
| `получить_расширение` | Идентификатор | Получение по ID |
| `вызвать_точку_расширения` | Имя, Параметры | Вызов хука |
| `количество_расширений` | - | Количество в реестре |

## Примеры использования

### Пример 1: Управление версиями проекта

```python
менеджер = СоздатьМенеджерВерсий()
менеджер.инициализировать_версию(7, 0, 3, "Начало разработки")

# Цикл разработки
for i in range(10):
    версия = менеджер.следующая_патч_версия()
    версия.добавить_изменение("Feature", f"Функция {i}")

# Крупное обновление
менеджер.следующая_минорная_версия()

# Сохранение истории
менеджер.сохранить_конфигурацию("version_history.json")
```

### Пример 2: Создание плагина с зависимостями

```python
реестр = СоздатьРеестрРасширений()

# Базовый плагин
плагин1 = СоздатьРасширение("core.validator", "Валидатор", "1.0.0")
плагин1.добавить_точку_расширения("ПередСохранением", validate_code)
реестр.зарегистрировать_расширение(плагин1)

# Зависимый плагин
плагин2 = СоздатьРасширение("doc.generator", "Документатор", "2.99.001")

реестр.зарегистрировать_расширение(плагин2)
```

```python
логгер = СоздатьЛоггер()
логгер.установить_файл_лога("/var/log/myapp.log")
```
